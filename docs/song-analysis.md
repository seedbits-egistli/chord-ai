# 歌曲分析（段落 + 主旋律）MVP

首頁改為「歌曲分析」；舊的和弦功能保留在 `/?legacy=1` 或 `/legacy`。全部在瀏覽器內執行，音訊不離開裝置。

## 流程
1. **人聲分離**：UMX-HQ（既有 worker）。與 **拍點/小節**（Beat This! small）平行執行。
2. **旋律**：CREPE small（`crepe-small.onnx`，6.5 MB）在人聲音軌上取 f0（20 ms hop，只跑有人聲的區段）。
   - 權重：marl/crepe（MIT）；ONNX 匯出：yqzhishen/onnxcrepe v1.1.0（MIT）。
   - f0 → 音符：信心 ≥ 0.5、5 格中值濾波、偏離 > 0.7 半音連續 2 格才切音、最短 90 ms、同音 < 60 ms 間隔合併；對齊到 1/4 拍格線。
3. **歌詞對齊**（有貼歌詞時）：既有 wav2vec2 CTC。
4. **段落**（`packages/chord-engine/src/v2/structure.ts`，傳統演算法，無訓練模型）：
   - 每小節 chroma（55–2000 Hz）+ MFCC(1–12)；自相似矩陣 = 0.6·chroma（2 小節上下文）+ 0.4·音色。
   - Foote 棋盤 novelty（半寬 4 小節）＋歌詞段落起點（+1.5）＋人聲開/關（+0.7）作為邊界獎勵；DP 切割，偏好 8/4/16 小節。
   - 標籤：歌詞三字母組 Dice > 0.55 視為重複；重複最多者 = 副歌；其他重複歌詞群接在副歌前 = 導歌，否則主歌；歌詞不同者預設主歌，與所有人聲段都不像且在副歌之後 = 橋段；無人聲：頭 = 前奏、尾 = 尾奏、中間 = 間奏。無歌詞時以音樂相似度分群，能量最高的重複群 = 副歌。
   - 代表旋律：同群各次出現，以 1/4 拍格線投票（音級投票、容許八度錯誤），半數以上有聲才保留。
5. **顯示**：段落色條（點擊跳轉、播放時高亮）、旋律鋼琴捲簾（小節線、音名、歌詞字）、播放線、目前音高亮、「旋律合成音」、「段落代表旋律」。

## 驗證
`BASE=http://localhost:5173 CHROME_PATH=... node scripts/verify-song-analysis.mjs <audio> [lyrics|-] <outDir> <name>`（音檔、歌詞只在本機，不進 repo）。

## v2 調整（2026-10-15）
- 段落改為粗粒度：相鄰同類段合併（上限約 70 秒）、人聲段至少 11.5 秒、器樂段至少 4 秒，過短者併入最相似的鄰段；總數超過 12 段時再合併最短段。
- 歌詞行若被 CTC 拉得比中位數長 2.5 倍以上（且超過 8 秒），不拿來判斷段落（避免獨奏被當副歌）。
- 旋律播放改用取樣鋼琴：FluidR3_GM acoustic grand piano（gleitz/midi-js-soundfonts，CC-BY 3.0；FluidR3 本身 MIT），放在 `web/public/samples/piano/`（約 530 KB，附 LICENSE.txt）。模式：原曲／原曲＋旋律（可調音量）／只有旋律。
- 播放時顯示目前歌詞行，逐字高亮；可匯出旋律 .mid（Type 0、PPQ 480、速度取拍點中位數）。

## v3（五線譜、滑音、時值）
- UI 切換「鋼琴捲簾 / 五線譜」。五線譜用 VexFlow 4.2（MIT）：調號（旋律音級 KS）、拍號 4/4、量化時值與休止符、歌詞、段落標、滑音 ⤵＋連線；播放時高亮目前小節／音並自動捲動。
- 滑音：連續 f0 平台之間的 portamento → `glideTo`；鋼琴以 playbackRate ramp 播放；MIDI 用 pitch bend。
- 時值：16 分格吸附 + 只允許常見時值；段落內重複投票統一節奏。
